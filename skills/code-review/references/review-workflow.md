# コードレビュー詳細観点

## 使い方

- 差分が小さい場合は「最優先観点」だけ確認する。
- 差分が大きい場合は上から順に確認し、問題が出た観点を深掘りする。

## 最優先観点

1. 認可、認証、秘密情報の取り扱いが破綻していないか。
2. 削除、更新、課金、通知などの副作用で誤操作が起きないか。
3. 失敗時にデータ不整合やリトライ不能状態を作らないか。

## 正しさ

- 条件分岐の抜け漏れがないか。
- 境界値と空入力の扱いが明確か。
- 既存 API 契約の入出力を壊していないか。
- エラー処理が呼び出し側の期待と一致しているか。

## 回帰

- 既存の正常系、異常系テストが変更影響をカバーできているか。
- フラグや設定値の既定動作が意図せず変わっていないか。
- 既存データや移行中データで壊れないか。

## 性能と運用

- N+1、不要な全件処理、過剰な同期処理がないか。
- タイムアウト、リトライ、サーキットブレーカの整合があるか。
- ログに機密や過剰情報が含まれないか。
- 障害解析に必要な観測点が不足していないか。

## 指摘テンプレート

- 問題: 具体的な不具合またはリスクを1文で示す。
- 根拠: 再現条件、該当コード、既存仕様との関係を示す。
- 修正案: 最小変更での対応方針を示す。
- 追加テスト: 再発防止の観点で1件以上提案する。
