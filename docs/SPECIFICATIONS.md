# Harness Installer Merge Specifications

## User Interface

標準入力からインストール先プロジェクトのパスと環境番号を受け取る。空入力、存在しない
パス、ディレクトリではないパス、未定義の環境番号は再試行せずエラー終了する。
引数なしは通常モード、`--override` は上書きモード、`--help` は使用法表示とする。
それ以外の引数はエラー終了する。

## Source and Destination

- ソース: `<installer-directory>/harness/<environment>/`
- 配置先: 利用者が入力したプロジェクトディレクトリ
- 配置規則: ソース直下の全内容を相対パスを保って配置先直下へ適用する

## Preflight

全ソースパスを列挙し、次の順で判定する。

1. 配置先が存在しなければ、新規配置対象とする。
2. 両方がディレクトリなら、配下の検査を継続する。
3. 両方が同一内容の通常ファイルなら、変更対象から除外する。
4. 両方が通常ファイルで対応形式なら、一時ディレクトリへマージ結果を生成する。
5. 上記以外、またはマージ失敗は競合とする。

競合が1件でもあれば、配置先を変更せず終了ステータス1を返す。

上書きモードでは、手順4のマージに代えてテンプレート通常ファイルを置換候補とする。
型の異なる同名パスとシンボリックリンクは、上書きモードでも競合とする。

## Merge Rules

### `.gitignore`

空行とコメントを重複判定から除外し、テンプレートにある無視パターンのうち、既存内容に
完全一致しないものだけを末尾へ追加する。既存の順序、コメント、改行は保持する。

### `.codex/hooks.json`

- ルートの `hooks` はオブジェクトでなければならない。
- イベントごとのグループは `matcher` の値で識別する。
- 同じグループ内のフックは `command` で識別する。
- 同じ command のオブジェクト全体が異なる場合は競合とする。
- 不足するグループまたは command だけを追加する。

### `.github/hooks/hooks.json`

- `version` は既存値とテンプレート値が一致しなければ競合とする。
- イベントごとのフックは `bash` で識別する。
- 同じ bash command のオブジェクト全体が異なる場合は競合とする。
- 不足するイベントまたは command だけを追加する。

### `.vscode/settings.json`

オブジェクトを再帰的に比較し、不足キーだけを追加する。同じキーの scalar、配列、または
型が異なる場合は競合とする。同一の値は再利用する。

### `Cargo.toml`

テンプレートの `[lints.clippy]` セクションにある代入をキーで識別する。配置先にセクション
またはキーがなければ追加し、同じキーの右辺が空白を除いて異なる場合は競合とする。

### `Makefile`

テンプレートのターゲット定義をターゲット名で識別し、関連するレシピを1ブロックとして
扱う。不足するターゲットブロックは末尾へ追加する。同名ターゲットが存在する場合、定義と
レシピが一致しなければ競合とする。

## Installation

Preflight 成功後、存在しないディレクトリを作成する。新規ファイルは `cp -p` で配置する。
マージ対象は配置先と同じディレクトリに一時ファイルを作り、既存モードを引き継いでから
`mv` で置換する。完成内容が既存内容と同一なら置換しない。
上書き対象はテンプレートの内容とモードを一時ファイルへ複製してから `mv` で置換する。
テンプレートに存在しない配置先パスは変更しない。

## Exit Status

- `0`: インストール成功。変更なしも含む。
- `1`: 入力不正、依存不足、テンプレート欠落、競合、構文不正、配置失敗。

## Verification Scenarios

1. 空の配置先へ各環境をインストールする。
2. 同じ環境を再実行し、内容と更新時刻が変わらないことを確認する。
3. 対応形式に既存設定がある状態で、不足設定だけが追加されることを確認する。
4. 同じ識別子の値違いで、配置先全体が変更されないことを確認する。
5. 不正な JSON、TOML 対象セクション、Makefile 定義を競合として扱う。
6. 未対応ファイル、パス型、シンボリックリンクを競合として扱う。
7. 新規ファイルと競合を混在させ、部分配置されないことを確認する。
8. 新規ファイルとマージ後ファイルのモードが仕様どおり保持されることを確認する。
9. `--override` が異なる既存ファイルをテンプレート内容とモードで置換することを確認する。
10. `--override` がテンプレート外のファイルを保持し、型衝突とシンボリックリンクを拒否することを確認する。
