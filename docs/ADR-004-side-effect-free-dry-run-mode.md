# ADR: Side-effect-free Dry-run Mode

## Status

Accepted

## Context

インストーラは全テンプレートパスを Preflight してから配置するが、利用者が実行前に
新規配置、意味的マージの対象を確認する手段がない。結果を確認するために一時的な
配置先を用意すると、実際のプロジェクトにある既存設定との競合を再現できない。

## Decision

`install.sh --dry-run` を追加する。通常実行と同じ入力検証、Preflight、マージ生成を行い、
成功後に新規配置、マージの予定パスと件数を表示する。配置先のディレクトリ作成、
ファイルコピー、置換、モード変更は行わない。

競合時は通常実行と同じエラーと終了ステータスを返す。対話項目は追加しない。

## Rationale

- 実配置と同じ Preflight を再利用することで、表示と実行の判定差を抑えられる。
- 配置フェーズ直前で終了すれば、副作用の境界が明確になる。
- 既存の2項目だけの対話を維持できる。

## Consequences

- マージ結果の生成には Python 3 と一時ディレクトリを使用するが、配置先には書き込まない。
- dry-run 成功後から通常実行までに配置先が変化した場合、後続実行の結果も変わり得る。
- 権限不足や容量不足など、実際の配置処理でだけ発生する I/O 障害は予測できない。

## Rejected Alternatives

### Skip Merge Generation

構文不正や意味的競合を見落とし、通常実行と異なる結果になるため採用しない。

### Write Temporary Files into the Destination

dry-run の副作用ゼロという契約を満たさず、監視ツールやビルド処理を発火させ得るため
採用しない。

### Add an Interactive Confirmation Step

自動実行を妨げ、利用者への質問を2項目に限定する既存要件に反するため採用しない。
