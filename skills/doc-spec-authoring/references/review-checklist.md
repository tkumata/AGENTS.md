# 文書レビュー観点

## 事実整合

- 仕様が実装と矛盾していない。
- 型、戻り値、エラー形式が現行コードと一致している。
- 外部契約の変更有無が明示されている。

## 完全性

- 正常系と異常系が両方定義されている。
- 境界値と制約が数値で示されている。
- 非機能要件が空欄になっていない。

## 検証可能性

- 受け入れ条件が観測可能な文で書かれている。
- テスト観点に直結する入力例がある。
- 期待結果が曖昧語なしで書かれている。

## 保守性

- 用語定義が一貫している。
- 改訂履歴または変更理由が追跡できる。
- 未定事項に判断者と期限がある。

## 品質ゲート

- 重大: 実装と矛盾する記述がない。
- 重要: 受け入れ条件と非機能要件が欠落していない。
- 推奨: 仕様変更時に移行方針が追記されている。
